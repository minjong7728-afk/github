# 하루기록

하루기록은 오늘 해야 할 일을 간단하게 작성하고 확인하는 웹페이지입니다.
공부, 운동, 생활 목표를 관리하고 싶은 사람이 이용할 수 있습니다.

## 7주차 - 목표 작성부터 완료까지

### 사용자와 목적

- 주요 사용자: 오늘 할 일을 간단하게 기록하고 싶은 사람
- 서비스 목적: 오늘의 목표를 작성하고 확인한 후 완료 여부를 확인하기
- 핵심 행동: 목표 내용과 종류를 선택하여 목표 완료하기
- 완료 조건: 확인 화면에서 '목표 완료하기' 버튼을 눌러 완료 화면이 표시되면 완료

### 사용자 흐름

1. '목표 시작하기' 버튼을 누릅니다.
2. 목표 내용을 입력하고 목표 종류(공부, 운동, 생활)를 선택합니다.
3. '목표 확인하기' 버튼을 눌러 입력한 내용을 확인합니다.
4. 틀린 내용이 있으면 '이전 단계' 버튼으로 돌아가 수정합니다.
5. '목표 완료하기' 버튼으로 완료 화면을 확인합니다.

### 인터랙션 시나리오

| 사용자 행동            | 이벤트        | 조건                            | 화면 반응                                      | 다음 상태                |
| ---------------------- | ------------- | ------------------------------- | ---------------------------------------------- | ------------------------ |
| 목표 시작하기 클릭     | click         | 없음                            | 목표 입력 화면 표시                            | 목표 작성                |
| 목표 입력 및 종류 선택 | input, change | 두 값 모두 입력·선택했는지 확인 | 안내 문구 변경, 확인 버튼 활성화 또는 비활성화 | 입력 유지 또는 확인 가능 |
| 목표 확인하기 클릭     | click         | 목표와 종류가 모두 있어야 함    | 목표 내용과 종류 표시                          | 확인                     |
| 이전 단계 클릭         | click         | 없음                            | 이전에 입력한 값 유지                          | 목표 작성                |

| 새 목표 시작하기 클릭  | click         | 없음                            | 입력값, 오류 안내, 진행 상태 초기화            | 처음                     |

### 7주차 테스트 결과

- [x] 목표와 종류를 입력하면 확인 화면에 반영된다.
- [x] 목표 또는 종류를 입력하지 않으면 다음 단계로 진행할 수 없다.
- [x] 이전 단계로 돌아가도 입력값이 유지되고, 수정 내용이 확인 화면에 반영된다.
- [x] 새 목표 시작하기를 누르면 작성 중인 내용이 초기화된다.
- [x] 모바일 화면에서 입력창과 버튼을 사용할 수 있다.

## 중간고사 - 완료한 목표 저장 및 기록 관리

### 7주차와 달라진 점

7주차에는 한 가지 목표를 작성하고 완료하는 흐름을 만들었습니다.
중간고사에서는 완료한 목표를 목록에 저장하고, 저장한 목표를 다시 확인하거나 삭제하는 기능을 추가했습니다.

### 사용자 흐름과 조건

| 사용자 행동               | 확인할 조건                           | 성공 시 반응                            | 다른 상태의 반응 및 다음 행동                                        |
| ------------------------- | ------------------------------------- | --------------------------------------- | -------------------------------------------------------------------- |
| 완료한 목표 저장하기 클릭 | 목표 완료 여부, 현재 목표의 저장 여부 | 목표와 종류가 '나의 목표 기록'에 추가됨 | 완료 전에는 먼저 완료하도록 안내, 이미 저장했다면 중복 저장하지 않음 |
| 저장 목록 확인            | 목록에 기록이 있는지 확인             | 저장한 목표와 개수 표시                 | 목록이 비었다면 목표를 완료한 뒤 저장하도록 안내                     |
| 기록 삭제 클릭            | 삭제할 기록이 목록에 있는 상태        | 해당 기록 삭제 및 남은 개수 표시        | 전부 삭제했다면 새 목표를 저장할 수 있음                             |
| 새 목표 시작하기 클릭     | 없음                                  | 작성 중인 값과 진행 상태 초기화         | 기존 저장 목록은 유지됨                                              |

### 중간고사 테스트 결과

- [x] 목표 완료 후 저장 버튼을 누르면 목록에 추가된다.
- [x] 저장 버튼을 반복해도 같은 완료 기록이 중복 저장되지 않는다.
- [x] 새 목표를 작성하고 저장하면 목록에 여러 기록이 보인다.
- [x] 삭제 버튼을 누르면 선택한 기록이 사라진다.
- [x] 기록을 모두 삭제하면 빈 목록 안내가 나온다.
- [x] 모바일 화면에서 목록과 삭제 버튼이 겹치지 않는다.

**테스트 확인:** 로컬 브라우저에서 목표 시작, 입력값 검사, 수정, 완료, 저장, 목록 표시, 중복 방지, 삭제, 초기화 및 모바일 조작을 시험했습니다. 총 18개 검사 항목에서 모두 정상 동작했습니다. 모바일은 375px 너비로 확인했습니다. 실제 GitHub Pages 배포 환경은 별도 확인이 필요합니다.

## 사용 기술

HTML, CSS, JavaScript를 사용했습니다. 별도 서버나 데이터베이스는 사용하지 않습니다.
목표 기록은 페이지를 새로고침하면 초기화됩니다.

## 9주차 - 목표 입력 폼 개선

### 추가한 기능

기존 목표 작성 화면에 목표 시간 설정 체크박스와 시간 입력란을 추가했습니다. 체크하면 시간이 나타나고, 체크하지 않으면 입력란이 숨겨지고 비활성화됩니다. 목표 입력은 3자 이상이어야 하며 종류를 선택해야 합니다.

### 입력 조건과 화면 반응

| 사용자 행동         | 조건                              | 화면 반응                                   |
| ------------------- | --------------------------------- | ------------------------------------------- |
| 목표 작성           | 3자 미만                          | 입력 글자 수와 수정 안내 표시               |
| 목표 종류 선택      | 미선택                            | 종류 선택 안내 표시                         |
| 목표 시간 설정 체크 | 시간 미입력                       | 시간 선택 또는 체크 해제 안내 표시          |
| 체크 해제           | 시간 사용 안 함                   | 시간 입력란 숨김 및 disabled 처리           |
| 목표 확인하기       | 조건 충족                         | 제출 중 버튼 비활성화 후 확인 화면으로 이동 |
| 등록 실패           | 브라우저 sessionStorage 사용 불가 | 입력 내용 유지, 재시도 문구 표시            |
| 새 목표 시작하기    | 완료 후 다시 시작                 | 현재 입력, 시간 선택, 안내 문구 초기화      |

### 9주차 테스트 결과

브라우저 자동화로 HTML, CSS, JavaScript를 불러와 입력과 버튼 동작을 확인했습니다. 모바일 화면은 375px 너비로 검사했습니다.

1. 빈 값으로 제출했을 때 오류 안내가 나오고 확인 화면으로 이동하지 않았습니다. (정상)
2. 목표를 1자로 입력했을 때 3자 이상 입력하라는 안내와 현재 글자 수가 표시되었습니다. (정상)
3. 목표를 3자 이상으로 수정했을 때 오류가 해제되고 현재 글자 수가 표시되었습니다. (정상)
4. 시간 설정 체크박스를 선택하면 시간 입력창이 나타나고 입력할 수 있었습니다. (정상)
5. 시간 설정을 선택하고 시간을 입력하지 않았을 때 제출이 제한되었습니다. (정상)
6. 시간을 입력한 뒤 제출하면 확인 화면에 입력한 시간이 표시되었습니다. (정상)
7. 이전 단계로 이동해도 목표, 종류, 시간 값이 유지되었습니다. (정상)
8. 시간 설정 체크를 해제하면 시간 입력창이 숨겨지고 disabled 처리되며 입력값이 비워졌습니다. (정상)
9. 목표 완료 후 저장 버튼을 누르면 목표 기록 목록에 추가되었습니다. (정상)
10. 새 목표 시작하기를 누르면 목표, 종류, 시간 설정, 안내 문구가 초기화되었습니다. (정상)
11. 모바일 375px 화면에서 가로로 화면이 넘치지 않았습니다. (정상)
12. 모바일 너비에서도 시간 입력창을 표시하고 조작할 수 있었습니다. (정상)
13. 브라우저 저장 기능의 오류를 인위적으로 발생시키면 실패 안내가 표시되고 입력값과 제출 버튼이 유지되었습니다. (정상)

**확인 결과:** 총 13개 항목 정상 통과. 실패 처리 테스트는 저장 기능 오류를 모의로 발생시켜 확인했습니다. 제출 중 문구와 버튼 비활성화는 코드에 구현되어 있지만, 처리가 즉시 끝나므로 실제 화면에서 지속적으로 표시되는지는 별도로 측정하지 않았습니다.

**확인 범위:** 자동화 시험에서는 페이지의 HTML, CSS, JavaScript를 브라우저에 직접 불러와 검사했습니다. GitHub Pages에 배포된 주소에서의 실제 동작은 업로드 후 별도 확인이 필요합니다.

**실패 처리 코드:** `script.js`의 `goalForm.addEventListener("submit", ...)` 부분에서 `sessionStorage.setItem(...)`에 오류가 발생하면 `catch`에서 오류 안내를 표시합니다. 오류가 발생하더라도 작성한 값은 지우지 않아 다시 제출할 수 있습니다.
